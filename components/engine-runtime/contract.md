# Vector persistent GPU game-search candidate

Owner-authorized implementation candidate for complete-suite task 6. VECTOR-0002 remains the implementation boundary; historical VECTOR-0001 and frozen model records are unchanged. Independent review and exact native qualification are required before product promotion.

`GameSearchPort` owns one game-lifetime GPU continuation and graph. Public methods are `ready()`, `admitPosition({fen,moves,rootEpoch,newGame})`, `requestPublication({rootEpoch,requestId,searchmoves})`, synchronous bounded `readPublication({rootEpoch,requestId})`, and `close()`. Admission returns `{rootEpoch,sideToMove}` only after GPU validation and a current legal publication candidate or terminal proof exists. Moves are externally supplied coordinate actions; GPU Domain applies and validates them. Cold FEN parsing is host admission, never active transition/search. Ordinary advancement preserves graph knowledge only after exact Domain equality/authority checks. Arbitrary replacements use GPU admission and new root authority. `ready()` cannot complete before all exact source/model/library/resource identities are admitted.

Publication returns null while a request is unpublished, otherwise `{rootEpoch,requestId,action,legalProof:{rootEpoch,action,legal:true},terminal}`. Null action requires `terminal:true` and current terminal proof. Root epoch/request identity and action are release-published by the GPU, read as one stable bounded snapshot. Host checks those fences and formats the action; it does no chess selection or legality calculation. Publication is read-only comparison over ready legal root records, has bounded latency independent of pending NN work, and cannot progress or reset search. `stop` requests publication, never terminates search. Only game replacement/quit/explicit teardown can retire the continuation.

UCI clocks select publication deadlines only. They never select work iteration count, graph attention, depth or NN admission. Protocol processing and timer callbacks cannot wait for active GPU completion. Parser/lifecycle tests may inject a protocol port; mocks do not qualify device search. Native qualification must bind the public MCGS canonical core, exact Domain 1.1/model-input sources, qualified Tensor block32 typed library and public CUDA-JS continuation cohort. No CPU search/feature/evaluator callbacks, native source, hand PTX or private imports are permitted.

Policy candidate: side-to-move NN value in [-1,1], legal-masked normalized policy priors, bounded PUCT selection, parent-perspective sign change on backup, terminal mate proof dominance, and deterministic read-only late root comparison. Complete normalized public profile/resource facts and independent tests must precede ignition. Each Tensor invocation requires all 32 threads in its block to call once with uniform item index. Search control and publication must never partially enter that callable.

Policy records contain six u32 words (visits, work reservation, proof, evaluated readiness, packed action, transaction generation) and four f32 words (completed sum, legal prior, cached NN value, reserved). Proof is unknown=0, owner-perspective win=1, loss=2, draw=3. A parent is proven win if any complete edge is win; proven loss if all complete edges are loss; draw if all are proven and at least one is draw. Empty/unexpanded views do not prove terminal truth. Full child views and terminal authority come through generic public MCGS callbacks; Policy cannot inspect Graph metadata.

Read-only publication compares complete encoded rows [action,visits,proof,biased mean,prior,reserved zero], six u32 words. Mean and prior use declared nearest 1e-6 quantization, mean biased by 1,000,000. This affects publication tie/comparison only; search PUCT and original NN mathematics remain f32. The row encoder validates before writes; malformed rows cannot produce a selection. CUDA-MCGS owns two immutable snapshot incarnations, borrow/retire lifetime and the eight-word authority envelope. Vector supplies only bounded row encoding and comparison; it does not overwrite borrowed ready payloads or maintain a second snapshot protocol.
