# Vector persistent GPU game-search candidate

Owner-authorized implementation candidate for complete-suite task 6. VECTOR-0002 remains the implementation boundary; historical VECTOR-0001 and frozen model records are unchanged. Independent review and exact native qualification are required before product promotion.

`GameSearchPort` owns one game-lifetime GPU continuation and graph. Public methods are lazy `ready()`, transactional `configure({name,value})`, `admitPosition({fen,moves,rootEpoch,newGame})`, `requestPublication({rootEpoch,requestId,searchmoves})`, synchronous bounded `readPublication({rootEpoch,requestId})`, `endGame()`, and `close()`. Admission returns `{rootEpoch,sideToMove}` only after GPU validation and current action-ready legal candidates or terminal proof exist. Moves are externally supplied coordinate actions; GPU Domain applies and validates them. Cold FEN parsing is host admission, never active transition/search. Ordinary advancement preserves graph knowledge only after exact Domain equality/authority checks. Arbitrary position admission changes root authority within the same game and retains off-focus knowledge. `ready()` cannot complete before all exact source/model/library/resource identities are admitted.

The advertised configuration is `ModelRoot`, a string. Initialization occurs only after supplied options are admitted. A failed replacement preserves the previously admitted model/configuration, blocks `readyok` for the rejected request, and requires a subsequent valid configuration. Configuration cannot change an admitted game. `ucinewgame` owns retirement intent and a fresh game authority; it does not rewrite Manager selection or preferences. Relative ModelRoot values resolve against the registered engine working directory. Packaged `models/default` declares model id `compact_chessformer_gab_v1`, display name `LatticeKnight-4M` and adapter `chess_v1_fen_to_dense_planes_v1`.

Publication returns null while a request is unpublished, otherwise `{rootEpoch,requestId,action,legalProof:{rootEpoch,action,legal:true},terminal}`. Null action requires `terminal:true` and current terminal proof. Root epoch/request identity and action are release-published by the GPU, read as one stable bounded snapshot. Host checks those fences and formats the action; it does no chess selection or legality calculation. Publication compares all already-ready canonical candidates in protected immutable output views. It never generates actions, expands graph children or advances search during observation. `stop` requests publication, never terminates search. Only game retirement/quit/explicit teardown can retire the continuation. Bounded latency during pending NN work remains a composed runtime qualification requirement.

UCI clocks select publication deadlines only. They never select work iteration count, graph attention, depth or NN admission. This candidate supports explicit `movetime` and `infinite` publication intents; remaining-clock allocation fails closed until an exact applicable timing-policy/useful-block artifact is qualified. No guessed remaining-clock fraction or historical native timing qualification is promoted. Ponder is not advertised. Protocol processing and timer callbacks cannot wait for active GPU completion. Parser/lifecycle tests may inject a protocol port; mocks do not qualify device search. Native qualification must bind the public MCGS canonical core, exact Domain 1.2/model-input sources, qualified Tensor block32 typed library and exact CUDA-JS alpha.22/Tensor alpha.10 cohort. No CPU search/feature/evaluator callbacks, native source, hand PTX or private imports are permitted.

Policy candidate: side-to-move NN value in [-1,1], legal-masked normalized policy priors, bounded PUCT selection, parent-perspective sign change on backup, terminal mate proof dominance, and deterministic read-only late root comparison. Complete normalized public profile/resource facts and independent tests must precede ignition. Each Tensor invocation requires all 32 threads in its block to call once with uniform item index. Policy records contain six u32 words (visits, work reservation, proof, evaluated readiness, packed action, transaction generation) and four f32 words (completed sum, legal prior, cached NN value, reserved). Proof is unknown=0, owner-perspective win=1, loss=2, draw=3. A parent is proven win if any complete edge is win; proven loss if all complete edges are loss; draw if all are proven and at least one is draw. Empty/unexpanded views do not prove terminal truth. Full child views and terminal authority come through generic public MCGS callbacks; Policy cannot inspect Graph metadata.

The selected finite stop hook continues below the 10,000,000-visit record limit, parks a proven root or a root at that limit, and fails malformed records. Parking preserves Session and read-only Output responsiveness; it does not use a clock or reset the graph. The physical `policy-resident-stop-observation.json` receipt adds these dispositions to the ready-result, transaction, abandon and retirement callback gate. Snapshot capture belongs to the device-owned quiescent boundary after the complete prepare/apply/complete/release path, or Session admission before the collective Evaluator body. Visits and sum cannot be captured between their separate writes; the composed core must prove that boundary and immutable-slot lifetime.
